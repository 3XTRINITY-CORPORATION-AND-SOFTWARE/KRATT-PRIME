# CHIRO-X Wave 2 failure-mode analysis

Method: hazard → root cause → detection → prevention → containment → recovery → regression test.

This is the pre-implementation failure model. “NOT IMPLEMENTED” means the baseline does not yet provide the control. A test name below is an acceptance requirement, not a claim that the test has run.

## Runtime failures

| Hazard | Root cause | Detection | Prevention and containment | Recovery and regression test | Baseline |
|---|---|---|---|---|---|
| Missing required task fields, oversized input, malformed agent result, or incompatible schema version | Untrusted or stale payload crosses a boundary | Versioned runtime validator returns a stable error before dispatch | Reject unknown critical fields/enums and cap payload bytes | Do not retry invalid data; test missing fields, size, malformed output, and version mismatch | Generic Wave 2 contract NOT IMPLEMENTED; PIP validators exist |
| Duplicate task, colliding identifier, duplicate event, or replayed event | Retry or client reconnect repeats an operation | Unique idempotency key/event ID and persisted transition lookup | Deduplicate at admission and event sink | Return original or conflict status; test duplicate task IDs, generated-ID collision, and event replay | Generic runtime NOT IMPLEMENTED |
| Missing/disabled agent, unavailable agent, or missing capability | Registry and task requirements disagree | Eligibility decision before scheduling | Fail closed; do not select an agent by model output | Leave task blocked or retry only availability failures; test each registry deny path | Registry scope checks exist; lifecycle/eligibility NOT IMPLEMENTED |
| Dependency cycle or unknown dependency | Invalid DAG | Graph validation at admission | Reject cyclic or dangling graph before enqueue | Preserve original request and report dependency error; test cycle and unknown-node cases | NOT IMPLEMENTED |
| Dependency never completes, queue overload, or unfair scheduling | Dead agent, saturated executor, or unstable ordering | Deadline and queue-depth counters | Bound concurrency/queue size and use deterministic priority/tie-break rules | Mark timed out or backpressure; never spin; test stalled dependency, overload, and stable order | NOT IMPLEMENTED |
| Deadline, retry budget, child-task, depth, memory, provider-call, or event-volume budget exceeded | Unbounded or exhausted resource | Monotonic elapsed-time and explicit counters | Validate finite limits before execution; check before each child/provider call | Mark TASK_BUDGET_EXCEEDED/TIMED_OUT; test every configured bound | NOT IMPLEMENTED |
| Partial work, agent crash, or process restart mid-execution | Side effect occurs before result is recorded, or state is only in memory | Persisted intent/lease state and incomplete step scan | Record step intent before side effect; isolate idempotent work | Recover only with a valid lease and reauthorization; otherwise RECOVERY_REQUIRED; test crash before/after result and restart | Generic durable DAG state NOT IMPLEMENTED |
| Agent publishes after cancellation or timeout; provider returns late | Async response races a terminal transition | Execution generation/lease and terminal-state check | AbortSignal plus fencing token; discard stale results | Preserve cancellation evidence and quarantine late output; test both cancellation races and late completion | NOT IMPLEMENTED in CHIRO pipeline |
| Out-of-order progress or status event | Multiple workers publish concurrently | Correlation ID, sequence/version, and transition validator | Accept only legal transitions; never assign status directly | Re-read durable task state and flag gaps; test out-of-order events and sequence gaps | PIP event envelope exists; sequence lifecycle NOT IMPLEMENTED |
| Incomplete Saga state, duplicate replay, or missing event history | Persistence failure or unsafe replay | Saga version, event history, and lease validation | Unknown state never maps to success; no side-effect replay without idempotency and approval | Stop as RECOVERY_REQUIRED and request reconciliation; test corrupt state, incomplete step, duplicate replay, and missing history | Saga helper is in-memory only |

## Authorization failures

| Hazard | Root cause | Detection | Prevention and containment | Recovery and regression test | Baseline |
|---|---|---|---|---|---|
| Missing, expired, wrong-scope, wrong-payload, wrong-policy, or wrong-request approval | Approval is absent, stale, or bound to a different action | Existing trusted KRATT verifier evaluates request-bound artifact and expiry | Deny before scheduling; never accept a model boolean | Append a safe denial event; test missing, expired, scope/hash/version/request mismatches | Existing verifier patterns; Wave 2 binding NOT IMPLEMENTED |
| Unverifiable approver identity or invalid issuer | Key registry/identity is unavailable or malformed | Trusted key lookup and signature verification fail | Fail closed and keep write/provider action disabled | Require independent reauthorization; test invalid key, identity, and signature | Existing trusted runtime supports injected keyring |
| Approval replay or nonce reuse | Duplicate request reuses an approval | Durable nonce store reports consumed nonce | Consume nonce transactionally with authorized intent | Reject replay and retain audit evidence; test concurrent/repeated nonce | Existing trusted runtime requires durable nonce store |
| Capability revoked after admission or child attempts self-escalation | Authority changes or agent output requests more scope | Recheck current registry/policy at execution boundary | Child scope is intersection only; no self-grant | Cancel/block stale task; test revoked capability and child escalation | Registry lacks revocation lifecycle |
| Model output attempts to grant permission or provider requests tool authority | Untrusted output is mistaken for authority | Strict schema contains no authority field; policy runtime is separate | Treat provider output as data; reject permission claims | Quarantine output; test forged permission field and tool request | Required regression |
| Request cancelled after approval or approval replayed during recovery | Approval remains attached to stale work | Task generation and policy expiry checked before every side effect | Cancellation invalidates outstanding execution context | Stop new work and record cancellation; test cancel-after-approval and recovery-after-expiry | NOT IMPLEMENTED |
| Conflicting policy versions or external write while disabled | Policy/configuration disagreement | Policy version and provider/write state checked at dispatch | Deny on conflict; external writes stay explicitly disabled | Reconcile under current policy; test conflicting version and disabled-write path | Existing policy handles decisions; Wave 2 adapter NOT IMPLEMENTED |

## Provider failures

| Hazard | Root cause | Detection | Prevention and containment | Recovery and regression test | Baseline |
|---|---|---|---|---|---|
| Provider timeout, unavailable service, or rate limit | Network/provider failure | Deadline, transport error, HTTP 429/Retry-After | Per-call timeout and bounded retry only for transient errors | Exponential bounded backoff with injected clock; test timeout, outage, and 429 | NOT IMPLEMENTED for CHIRO |
| Malformed, incomplete, wrong-content-type, invalid JSON/schema, or truncated response | Provider drift or corrupt response | Adapter validates status, content type, byte limit, schema | Treat all response data as untrusted; reject before downstream stage | Map to PROVIDER_RESPONSE_INVALID; test malformed/truncated/partial payloads | Output PIP validation exists after the provider |
| Provider capability changes or refusal | Model no longer supports requested modality/format | Capability registry and explicit refusal mapping | Never infer capability from model name alone | Mark unsupported/blocked; test capability mismatch and refusal | No capability registry |
| Oversized or unexpected provider payload, embedded instructions, or untrusted content | Provider response exceeds resource/privacy contract | Byte/shape limits and schema validation | Do not execute provider instructions; strip unrelated context | Quarantine response and emit safe error; test oversized, hostile, and unknown fields | NOT IMPLEMENTED |
| Cancellation during transmission or late response | Request is already in flight | AbortSignal and execution generation check | Cancel transport where supported; fence result even if transport cannot abort | Discard late response; test abort and late completion | NOT IMPLEMENTED |
| Retry duplicates a non-idempotent operation | Retry policy lacks operation semantics | Idempotency metadata and operation classification | Do not retry permanent errors or unkeyed writes | Mark outcome uncertain for reconciliation; test duplicate dispatch and no-retry classes | Existing outbox is at-least-once |
| Private payload routed remotely or automatic fallback switches local to remote | Router ignores consent/classification | Policy check at provider selection and immediately before send | External provider disabled by default; fallback may not weaken privacy | Block and record policy violation without payload; test local-only and missing-consent routing | CHIRO currently passes mode but does not enforce provider choice |

## Evidence failures

| Hazard | Root cause | Detection | Prevention and containment | Recovery and regression test | Baseline |
|---|---|---|---|---|---|
| Missing, inaccessible, outdated, unattributed, or unverifiable source | Reference is not a verifiable evidence object | Independent source verifier checks existence/accessibility/date/provenance separately | Keep each verification dimension distinct | Mark insufficient or blocked and request evidence; test every missing/unavailable/stale case | PIP has source IDs; no PIP source adapter |
| Claim has no evidence, unsupported source link, dangling graph edge, or evidence cycle | Claim/reference graph is incomplete or circular | Graph/claim validator and MÕTLEMINE dependency analysis | No support status without verified links; reject prohibited cycles | Preserve claim as unverified and produce correction proposal; test missing/dangling/cycle cases | MÕTLEMINE checks claim cycles; PIP linkage absent |
| One source counted multiple times through derivative copies | Independence is based on URL/count rather than origin | Source dependency key and derivative relationship | Count independent origins, not duplicate references | Report dependence; test copies and shared underlying source | MÕTLEMINE groups same source IDs |
| Model-generated claim used to verify itself | Verifier trusts producer or model agreement | Provenance type and verifier identity check | Require independent verifier; model output is never evidence of its own claim | Block and retain provenance; test self-verification attempts | Existing CHIRO injected verifier does not prove independence itself |
| Conflicting sources silently discarded or contradiction class hidden | Pipeline keeps only selected claim | Conflict report preserves support and refute references | No source is deleted by Anti-Talmud; explain type/severity | Keep competing interpretations and request human review; test direct, temporal, scope, definition, measurement, attribution, version, and contextual conflicts | MÕTLEMINE reports conflict; typed PIP categories NOT IMPLEMENTED |
| Correction loses original claim or provenance | Correction mutates or replaces source result | Before/after digest and immutable correction record | Correction is proposal-only; retain original claim, sources, reason, replacement, reviewer status | Human approval required; test correction preservation and no auto-apply | Meridian emits proposals for Word Semantic only |
| Confidence is arbitrary or presented as calibrated probability | Model score is treated as statistical calibration | UI/API schema labels score as uncalibrated unless a dataset-backed calibration record exists | No confidence-to-truth mapping | Abstain or show uncertainty; test uncalibrated score labels and dataset provenance | No PIP calibration dataset |
| Verification history or evidence provenance is incomplete | Audit/graph write failed | Append result and integrity verification | Fail closed when required evidence history cannot be stored | Mark persistence failure; do not return supported; test sink failure and incomplete history | Wave 10 exists for operations, not PIP evidence |

## Data and privacy failures

| Hazard | Root cause | Detection | Prevention and containment | Recovery and regression test | Baseline |
|---|---|---|---|---|---|
| Consent missing, invalid, or revoked | Request has no current consent record | Consent record/version checked at admission and before provider call | Deny processing; no fallback | Cancel and record safe denial; test absent, revoked, wrong-subject, and stale consent | PIP boolean consent only |
| Sensitive image uploaded or raw bytes embedded in task/log | Adapter uses raw data or uncontrolled logging | Payload-size and data-classification checks; log redaction test | Use opaque asset references; no image bytes in task/event/log | Delete only according to documented retention policy; test byte rejection and canary redaction | PIP excludes raw bytes; provider transport not enforced |
| Data classification missing or routing violates privacy | Missing policy metadata or provider mismatch | Validate classification and provider location/mode | Deny external route unless approved; do not infer permission | Keep local/unbound status; test classification required and route denial | NOT IMPLEMENTED |
| Input size/dimensions exceed limits | No resource cap or decompression bomb | Preflight byte/dimension/content-type checks | Reject before decode/upload; bounded decoder | Return safe validation error; test oversized and malformed media | NOT IMPLEMENTED |
| Retention exceeds consent or redaction fails | Storage/log lifecycle mismatch | Retention metadata, deletion receipts, redaction canary tests | Separate raw retention approval from processing consent | Block persistence/export; test retention expiry and redaction failure | PIP flags exist; retention store absent |
| Test fixture contains real personal data | Fixture origin not reviewed | Fixture inventory and synthetic/public-domain policy | Use synthetic data only; no real private images | Remove fixture and rerun scan; test fixture classification | No Wave 2 fixture inventory |

## UI and operational failures

| Hazard | Root cause | Detection | Prevention and containment | Recovery and regression test | Baseline |
|---|---|---|---|---|---|
| Repeated cancellation click | UI sends duplicate intent | Idempotency key and disabled pending control | Repeated cancellation is safe | Render one terminal state; test repeated clicks and request dedupe | Wave 2 UI absent |
| Stale status, missing correlation, duplicate/out-of-order reconnect events | UI assumes ordered delivery | Sequence, correlation, last-updated time, and bounded refresh | Deduplicate and flag stale state | Re-read protected API; test duplicate, stale, and reordered events | Current Desk has no task events |
| Unverified claim shown as fact or unknown status shown as success | UI maps unknown values to success style | Explicit status allowlist and accessible text | Unknown/partial/blocked states remain explicit | Render error/unknown state; test each status mapping | Wave 2 UI absent |
| Provider shown as connected merely because configured | Configuration mistaken for health | Read actual health and authorization status separately | Show unbound/disabled until verified health response | Refresh protected status; test configured-but-unhealthy provider | Wave 2 provider UI absent |
| UI cannot cancel or shows success after cancellation | Stale result races cancellation | Task generation/status from backend | UI never locally promotes status; cancel response is not completion | Await authoritative state; test cancel/late-completion race | No task API |
| Keyboard/accessibility state hides an action or status depends on color | Inaccessible component or visual-only status | Keyboard and semantic accessibility checks | Native controls, focus state, labels, text status | Preserve user context on error; test keyboard/status labels/reduced motion | Existing Desk has base accessibility checks |
| Network/API error, unknown status, or error boundary failure | Route absent, malformed, or unavailable | HTTP state mapping and response validator | Show explicit unbound/denied/degraded/error; never infer live runtime | Bounded retry by user action; test 401/403/404/503/timeout/malformed | Existing Observatory mapping, no Wave 2 route |
| Diagnostic panel leaks payload, private image reference, or credentials | UI renders raw server error/diagnostic object | Snapshot/canary privacy test | Render allowlisted fields only | Clear sensitive view and retain safe event ID; test private payload exclusion | NOT IMPLEMENTED for Wave 2 |

## Deployment and shutdown

| Hazard | Root cause | Detection | Prevention | Recovery and regression test | Baseline |
|---|---|---|---|---|---|
| CI branch event deploys or publishes unexpectedly | Workflow has an unreviewed deployment step | Review triggers and every job before branch creation | Only validation workflows may be enabled for Wave 2; no deployment token or environment | Stop and record; test workflow trigger/permissions and inspect Actions | Inspected CHIRO workflows are validation/build only |
| Shutdown leaves provider calls or leases active | Worker has no bounded drain/fencing | Shutdown health and active lease count | Stop admission, abort work, expire/fence leases safely | Mark unfinished work recovery-required; test shutdown during each stage | Generic runtime NOT IMPLEMENTED |
